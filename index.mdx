cap-std replaces Rust's ambient-authority filesystem, networking, and time APIs with capability-based equivalents. Instead of opening any file on the system by absolute path, you pass around `Dir` and `Pool` handles that scope what your code can access — making sandboxing fine-grained, composable, and built into your program's type system.

## Why Capability-Based Security?

Standard Rust (like most languages) uses *ambient authority*: any code in your process can open any file, connect to any address, or read the system clock, simply by naming it. This makes sandboxing coarse-grained — you either trust a library completely or not at all.

cap-std makes access explicit. A function that receives a `Dir` can only access files within that directory. A function that receives a `Pool` can only connect to the addresses in that pool. There's no way to escape the sandbox using `..`, absolute paths, or symlinks that point outside.
